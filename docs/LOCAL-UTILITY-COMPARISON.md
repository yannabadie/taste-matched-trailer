# Local editing comparison, 23 October 2026

The delivered sound-off workbench completed the editing tasks below, but a
prepared, competent JSON editor completed them too. The initial workbench lost
its in-memory draft on reload and required manual reconstruction from the saved
file. The single follow-up change adds local reopening of that file. This repairs
a basic document capability; it does not establish superiority over the editor.

This is an executed technical operator comparison on **one authentic dated
parent**, not an author study, a creative preference result or a new cultural
acquisition. Provider response data and parent-attached JSON exports are not
published in this report.

## What was held equal

Both paths received the same complete four-shot parent recorded on 20 October,
its original UTF-8 export, narration, captions, image descriptions, constraints,
shot order and timings. Both received identical prepared caption proposals;
the four strings were compared exactly. No new Qloo request, model generation,
native verification, run family or rendered media was needed for these tasks.
The engine remains **2.6.3** and runtime **1.1.3**.

The alternative was a readable export plus a programmable JSON editor recipe,
with validation, source hashing, modification, saving and reopening. Its recipe
was independently implemented without calling the workbench core. Preparing
that recipe is declared setup, not an ordinary stock editor feature or free
construction. Its file format could differ from ours; task completion did not
require reproducing our proprietary JSON structure. Both paths could preserve
the exact source and editing decision.

The workbench was the actual8145ac6 source in a network-disabled local browser
replay. The same operator knew the scenario and the target correction in both
paths. This comparison can reveal losses and recovery steps; it cannot estimate
human learning, effort, reading time or artistic preference.

The browser accept/reject downloads were read back independently. Payload hashes,
derived IDs, exact parent bytes, the requested caption, silent audio fields and
unchanged images/durations matched. The original parent's native sound setting
remained unchanged; the local derivative had no native verification.

The recorded operations distinguish recipe invocations, field edits, GUI clicks,
file reads and setup. These are different units. Their counts are not converted
into a speed ranking or minutes saved by an author.

Three further **synthetic controls** preserve limitations rather than adding
authentic cases: already complete captions produced no lexical gap in either
path; overlong text with fixed timing produced warnings in both; deliberately
story-breaking free text produced no structural error in either. A structurally
valid caption can still damage the canon. Semantic review remains unperformed.

## One result-driven change: reopen the local decision

The new **Resume a saved local decision** action reads a local JSON file of at
most1MiB. Before replacing the editor it checks the supported schema/kind,
derived identity, payload hash, the exact current parent UTF-8 bytes and protected
shot fields. It restores only captions and the note into an **undecided draft**.
The historical accept/reject decision is identified as history; accept or reject
again before downloading. An invalid file leaves the current draft and decision
intact. No URL from the file is followed and no new service is involved.

The hash is application-format integrity checking, not source authentication,
RFC8785 or independent approval of the words. Canon, spoilers and comprehension
remain unverified. A parent's native verdict never certifies the resumed draft.

Reception distinguishes two levels:

- Seventeen targeted source/isolated-handler checks passed, including identity
  tampering, protected fields changed even with a new hash, a different parent,
  invalid/oversized files, optional metadata, rejected missing text and an edit
  made while file reading was in progress. The two delivered HTML copies contain
  the tested core.
- Root then received the actual isolated browser path: an earlier real accept
  export restored the exact second caption and note, with download disabled;
  a fresh decision produced a new downloaded export; an unsupported file kind left that
  accepted text, note and decision intact; reload and reimport of the new export
  restored the same content as an undecided draft again. This browser reception
  used the in-app browser. The Chrome extension's file-selection permission
  blocked our earlier automated file selection; that was not counted as a
  successful import and no permission was added.

The initial comparison and its editor advantage are retained separately from
this delta. Reopening now addresses that observed deficit; no new author
preference, time saving or broad product advantage follows from it.

## Boundary of the claim

The official kit already supplies a conversational agent, CLI and MCP routes;
normalized routes share workflows/results. Ranking and other taste workflows
are already documented capabilities. Connecting a writer to those capabilities
is not, by itself, a new product difference. [Official kit](https://github.com/qloo/qloo-hackathon-kit),
[MCP starter](https://github.com/qloo/qloo-hackathon-kit/blob/main/starter/mcp-client/README.md).

What is concretely received here is a local interface for inspecting where
received words enter a caption, editing a particular shot, keeping source and
decision separate, and reopening that work. A prepared document can provide
the same outcomes. Whether this interface helps an actual author more is still
unmeasured. No better art, causal benefit from cultural affinities, customer
endorsement, sales effect or global novelty is claimed.

## Separate offline writing pilot: no creative advantage demonstrated

Three fresh Codex contexts produced one first draft each from the same competent
prompt, synopsis, alphabetically ordered candidate catalogue, language, output
schema and requested word ceiling. A received no measured cultural evidence;
B added documented kit capabilities and dated fields already exposed by the
public reader; C added the versioned application selector, shot scaffold and
local-layer limits to B. No condition received the finished historical Qwen
images or prose. This tests combined information/contract packets, not candidate
discovery or an isolated application component.

Production order was randomized before the first answer; review delivery order
was shuffled separately. The reviewer froze the criteria before outputs and
scores before unmasking. Only labels were hidden: source language in the drafts
gave provenance clues, and the single AI reader already knew the products. This
was not double-blind or a human author evaluation. Model selection was omitted
to inherit the parent configuration and maximum effort was requested; the spawn
API returned no per-call provider/model metadata. Equal requested output limits
and configuration do not establish equal effective compute. There was no retry
or conditional repair of a first draft.

The frozen scale was0/1/2 or not assessable, with no sum or overall score.
Here2 means no relevant defect identified on that written criterion, not
perfection or a field-validated outcome.

| Frozen criterion | A: no measurements | B: public cultural information | C: B plus app context |
| --- | --- | --- | --- |
| Q1: Fidelity to the supplied canon and exact task | 2 | 2 | 1 |
| Q2: Silent information and feasible constraints | 2 | 2 | 1 |
| Q3: Concrete next editorial decision | 2 | 2 | 2 |
| Q4: Evidence and cultural attribution | 2 | 2 | 2 |

A and B tied on these four criteria. C introduced an unprovided material-trace
motif and conveyed the sensed presence less explicitly without sound. These
were a reader's concerns requiring an editorial decision, not an established
hard violation. The same underlying concern informs Q1 and Q2 and must not be
added as two independent failures. All three offered a concrete next decision
and separated cultural association from creative interpretation. Artifact
recovery and setup/intervention burden were **not assessable** from these
written drafts; their runtime or human-time behavior was not scored.

No improvement from B over A or C over B was demonstrated on this one synopsis.
The material-trace scaffold may constrain this sparse canon poorly; this is a
bounded lesson from one AI reading, not grounds to change the engine or native
contract on its own. The unfavorable first answer is retained and C is not
rerun to seek a win. No new Qloo, kit, Qwen or application execution, provider
causal benefit, rendered comprehension, user preference or sales effect is
established. Full outputs and provider fields remain outside the public report.
